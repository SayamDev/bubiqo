# Job Brief Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Bubiqo's job-advert reading with a `JobBrief` that answers "is this worth an hour" — blockers, money, closing date, working pattern — sourced from schema.org JSON-LD where the page has it and from prose where it does not.

**Architecture:** Two new pure core modules. `core/job-posting.ts` normalises JSON-LD `JobPosting` blocks; `core/job-brief.ts` assembles a `JobBrief`, with structured values beating prose field by field and every field carrying its provenance. `core/analyse.ts` builds the brief when the Surface is `job`, before the Problem Radar runs, and the radar reads blockers from the brief instead of sniffing entity strings. `core/job-details.ts` and the `skill`/`requirement` Entity types are deleted.

**Tech Stack:** TypeScript, Vitest, React 18 side panel, Chrome MV3. No new dependencies.

## Global Constraints

- `extension/src/core/**` may not import `chrome.*`, the DOM, or React. Pure functions over plain data.
- Determinism: identical `PageContext` + identical `now` produce an identical `JobBrief`.
- Never invent a value. A field that cannot be read with evidence is absent, not guessed.
- `verdict` is only ever `"ruled_out"`, and only when a blocker matched with a quoted sentence.
- `npm run verify` (typecheck + lint + test + build) must pass before any task is considered done.
- British English in user-facing copy, matching the existing panel.

- [ ] **Step 3: Implement `readJobPosting`**

Guardrails for the implementation:
- Flatten `@graph` arrays into the candidate list before matching.
- `@type` may be a string or an array of strings; match `JobPosting` in either.
- Read strings defensively: a helper `str(v)` returns `undefined` for anything that is not a non-empty string, so an object-valued `title` is skipped rather than stringified to `[object Object]`.
- Salary formatting reuses `formatAmount` / `formatRange` from `core/money.ts`. `currency` may sit on the `MonetaryAmount`; `value` may be a `QuantitativeValue` with `minValue`/`maxValue`, a `QuantitativeValue` with `value`, or a bare number.
- `jobLocation` may be a string, a `Place` with a `PostalAddress`, or an array of either. Take the first readable locality, falling back to `addressRegion` then `addressCountry`.
- Every field is optional. Return `null` only when no `JobPosting` block exists at all.

### Task 3: Brief assembly, blocker rules, eligibility section

**Files:**
- Create: `extension/src/core/job-brief.ts`
- Test: `tests/job-brief.test.ts`

**Interfaces:**
- Consumes: `readJobPosting` (Task 1); `JobBrief`, `Blocker`, `BriefField` (Task 2); `resolveDates` from `core/dates.ts`; `formatRange`/`formatAmount`/`readNumber`/`looksLikeSalary` from `core/money.ts`.
- Produces: `buildJobBrief(page: PageContext, now: number): JobBrief`, and `BLOCKER_RULES` exported for testing.

**Blocker rules** — id, pattern, summary. These six and no others:

| id | matches | summary |
|---|---|---|
| `security_clearance` | security clearance, SC cleared, DV cleared, developed vetting, BPSS, NPPV, counter-terrorist check | Security clearance required |
| `british_citizen` | British citizen(ship), sole British national, must be a UK citizen | Must be a British citizen |
| `uk_residency` | lived/resided in the UK for N years | UK residency period required |
| `right_to_work` | right to work, work permit, cannot/unable to sponsor, no sponsorship, visa sponsorship is not | Right to work restrictions |
| `driving_licence` | full/valid/clean (UK) driving licence | Driving licence required |
| `dbs_check` | DBS check, enhanced DBS, criminal record check | DBS check required |

Years-of-experience, degree requirements and on-site days are **not** blockers. On-site days become `workingPattern`; the rest are left to the eligibility quotes.

import { describe, it, expect } from "vitest";
import { buildJobBrief } from "@core/job-brief";
import type { PageContext } from "@core/types";

const NOW = Date.UTC(2026, 8, 12);

function page(over: Partial<PageContext> = {}): PageContext {
  return {
    url: "https://example.com/job", domain: "example.com", title: "A job",
    text: "", headings: [], fields: [], structuredData: [], links: [],
    capturedAt: NOW, ...over,
  };
}

describe("buildJobBrief — blockers", () => {
  it("flags security clearance with the advert's own sentence", () => {
    const brief = buildJobBrief(page({
      text: "About the role. You must hold active SC cleared status before starting. We offer a pension.",
    }), NOW);
    const blocker = brief.blockers.find((b) => b.rule === "security_clearance");
    expect(blocker?.summary).toBe("Security clearance required");
    expect(blocker?.evidence).toMatch(/SC cleared/);
    expect(brief.verdict).toBe("ruled_out");
  });

  it("flags a citizenship requirement written as a bullet", () => {
    const brief = buildJobBrief(page({ text: "To Be Eligible, You Must\nBe a British citizen." }), NOW);
    expect(brief.blockers.map((b) => b.rule)).toContain("british_citizen");
  });

  it("flags an inability to sponsor", () => {
    const brief = buildJobBrief(page({ text: "We are unable to sponsor visas for this role." }), NOW);
    expect(brief.blockers.map((b) => b.rule)).toContain("right_to_work");
  });

  it("flags a residency period", () => {
    const brief = buildJobBrief(page({ text: "You must have resided in the UK for the last five years." }), NOW);
    expect(brief.blockers.map((b) => b.rule)).toContain("uk_residency");
  });

  it("flags a driving licence", () => {
    const brief = buildJobBrief(page({ text: "A full UK driving licence is essential for this post." }), NOW);
    expect(brief.blockers.map((b) => b.rule)).toContain("driving_licence");
  });

  it("flags a DBS check", () => {
    const brief = buildJobBrief(page({ text: "This post is subject to an enhanced DBS check." }), NOW);
    expect(brief.blockers.map((b) => b.rule)).toContain("dbs_check");
  });

  it("gives no verdict when nothing blocks", () => {
    const brief = buildJobBrief(page({
      text: "A friendly team looking for someone to help with events. 3 years' experience preferred.",
    }), NOW);
    expect(brief.blockers).toHaveLength(0);
    expect(brief.verdict).toBeUndefined();
  });

  it("treats years of experience as no blocker at all", () => {
    const brief = buildJobBrief(page({ text: "You will have 5+ years' commercial experience." }), NOW);
    expect(brief.blockers).toHaveLength(0);
  });
});

describe("buildJobBrief — structured beats prose", () => {
  const structured = [{
    "@type": "JobPosting",
    title: "Senior Frontend Engineer",
    hiringOrganization: { name: "Halcyon Labs Ltd" },
    baseSalary: { currency: "GBP", value: { minValue: 45000, maxValue: 60000 } },
    validThrough: "2026-10-01",
  }];

  it("prefers the site's own statement of the facts", () => {
    const brief = buildJobBrief(page({
      structuredData: structured,
      title: "Jobs | ExampleBoard",
      text: "Salary £30,000 – £35,000 for a Junior Developer at SomeoneElse Ltd.",
    }), NOW);
    expect(brief.title?.value).toBe("Senior Frontend Engineer");
    expect(brief.title?.source).toBe("structured");
    expect(brief.organisation?.value).toBe("Halcyon Labs Ltd");
    expect(brief.salary?.value).toBe("GBP 45,000–60,000");
    expect(brief.closingDate?.value).toBe(Date.UTC(2026, 9, 1));
  });

  it("falls back to prose when there is no structured data", () => {
    const brief = buildJobBrief(page({
      headings: ["Senior Frontend Engineer"],
      text: "Salary £45,000 – £60,000 per annum. Hybrid, 2 days on-site.",
    }), NOW);
    expect(brief.salary?.value).toBe("GBP 45,000–60,000");
    expect(brief.salary?.source).toBe("prose");
    expect(brief.workingPattern?.value).toMatch(/2 days on-site/i);
  });
});

describe("buildJobBrief — eligibility quotes", () => {
  it("quotes the advert's own eligibility bullets", () => {
    const brief = buildJobBrief(page({
      headings: ["To Be Eligible, You Must"],
      text: [
        "About the role. We build things.",
        "To Be Eligible, You Must",
        "Hold a current first aid certificate",
        "Be available for weekend shifts",
        "What we offer",
        "A pension and 25 days holiday",
      ].join("\n"),
    }), NOW);
    expect(brief.eligibility).toContain("Hold a current first aid certificate");
    expect(brief.eligibility).toContain("Be available for weekend shifts");
    expect(brief.eligibility).not.toContain("A pension and 25 days holiday");
  });

  it("caps the quotes", () => {
    const lines = Array.from({ length: 20 }, (_, i) => `Requirement number ${i}`);
    const brief = buildJobBrief(page({
      headings: ["Essential requirements"],
      text: ["Essential requirements", ...lines].join("\n"),
    }), NOW);
    expect(brief.eligibility.length).toBeLessThanOrEqual(8);
  });

  it("is deterministic", () => {
    const p = page({ text: "You must hold SC cleared status. Salary £50,000 per annum." });
    expect(buildJobBrief(p, NOW)).toEqual(buildJobBrief(p, NOW));
  });
});

- [ ] **Step 3: Implement `buildJobBrief`**

Guardrails:
- Evidence for a blocker is the sentence or line containing the match, trimmed to 180 characters. A line break counts as a sentence boundary — adverts state eligibility as bullets with no full stops, and a full-stop-only window swallows the whole section.
- `closingDate` from structured data parses `validThrough` as an ISO date directly. From prose it uses `resolveDates` on the sentence around "closing date" / "applications close", which refuses ambiguous numeric dates by design.
- Salary from prose: find a currency range or single amount, reject values failing `looksLikeSalary`, format through `core/money.ts`.
- `workingPattern` from prose: N days on-site, fully on-site, hybrid, or remote. From structured data: `employmentType`.
- Eligibility section: locate a heading matching `/eligib|essential|you must|what you.ll need|requirements|security requirements|to apply/i` in `page.headings` or as a line under 80 characters in the text. Take following non-empty lines until the next such short line that looks like a heading, capped at 8 items, 400 characters total, each trimmed to 180.
- `verdict` is `"ruled_out"` when `blockers.length > 0`, otherwise omitted.

## As built (2026-09-12)

Tasks 1–6 are done. Three deviations from the plan, each forced by evidence:

1. **`buildJobBrief(page, entities, now)`**, not `(page, now)`. Prose salary is taken
   from the amount Entity the engine already chose rather than re-matched. An Indeed
   job page carries four salaries — three belonging to other adverts in the rail — and
   a second rule for picking between them would have disagreed with the first.
2. **The prose title comes from `preferredTitle`** in `core/storage-hygiene.ts`, which
   already knew that LinkedIn's first heading is a feedback widget. Reimplementing it
   produced briefs titled "Are these results helpful?" and "Welcome, Sayam".
3. **Every eligibility section is collected, not the first**, and a heading must be both
   short and unpunctuated. "Consultancy experience would be helpful, but it is not
   essential." was opening a section and quoting the real heading below it as a
   requirement.

Salary strings use `core/money.ts` formatting — `GBP 45000–60000`, without thousands
separators — matching the amount Entities rather than introducing a second format.

**Task 7 is part-done.** `npm run capture-snippet` now builds the capture harness, and a
Greenhouse-hosted posting has been checked: no JSON-LD there either, which makes five
real pages in a row. See `docs/CAPTURING-FIXTURES.md`. What is left needs a logged-in
browser — LinkedIn, Indeed, a Lever or Workday posting, and a public-sector advert — and
that is a human's job because it happens inside their own session.

**The panel is verified.** `.preview` renders `JobBriefBlock` against the captured pages
in light and dark, and it found three flaws that the unit tests could not: a salary
shown in storage format, blockers with no wording saying the reader was ruled out, and
the eligibility disclosure wearing the "why?" chrome. Fixed.
